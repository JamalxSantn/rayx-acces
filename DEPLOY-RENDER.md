# Deploy: Rayx Acces on Render

Two Render services, both from this one repo:

| Service | Type | Command | Purpose |
|---|---|---|---|
| `rayx-acces-web` | Web Service (Node) | `npm start` | API + built React panel on one URL |
| `rayx-acces-bot` | Background Worker (Node) | `npm run bot` | Discord bot (tickets, logs, slash commands) |

`render.yaml` in the repo root describes both, including a 1 GB disk on each
(SQLite + bot state must survive deploys).

---

## 0. Prerequisites

- Repo pushed to GitHub (private is fine).
- Render account: <https://dashboard.render.com>

Push the repo (once):

```bash
cd "C:\Users\Jamal\Desktop\quantix\quantix\Mxstafa Auth"
git remote add origin https://github.com/<YOUR-USER>/<YOUR-REPO>.git
git push -u origin main
```

`.gitignore` already keeps `server/.env`, `bot/config.json`, `server/data/`,
`bot/data/`, `client/dist/` and `node_modules/` out of git. **No secrets are
committed** — everything sensitive is an env var in Render.

---

## 1. Create the services (Blueprint)

1. Dashboard → **New +** → **Blueprint**.
2. Connect the GitHub repo, branch `main`.
3. Render reads `render.yaml`, shows both services → **Apply**.

Or manually: **New +** → **Web Service** and **New +** → **Background Worker**,
with the build/start commands from the table above.

---

## 2. Fill the secrets

Blueprint deploy asks for every `sync: false` value.

**Web service (`rayx-acces-web`)**

| Key | Value |
|---|---|
| `BOT_API_KEY` | a long random hex string — generate with `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `SECRET_PHRASE` | your hidden owner password (login form) |

`JWT_SECRET` is generated by Render automatically and stays stable.

**Worker (`rayx-acces-bot`)**

| Key | Value |
|---|---|
| `BOT_TOKEN` | the Discord bot token (same one as local `bot/config.json`) |
| `BOT_API_KEY` | **exactly the same value** as on the web service |

Everything else (guild / role / category / channel IDs, `API_BASE_URL`,
`SITE_URL`) is already in `render.yaml`. `API_BASE_URL` and `SITE_URL` are
pulled from the web service host automatically, and the code adds `https://`.

---

## 3. First boot

1. Web service → **Logs**. On the very first start the empty database creates a
   bootstrap registration key:

   ```
   Rayx Acces - bootstrap registration key
   RAYX-REG-XXXXX-XXXXX
   ```

2. Open `https://<your-service>.onrender.com` → **Register** → use that key,
   pick username/password → set up the authenticator code → admin account done.
3. Worker → **Logs** should show:

   ```
   [Rayx Acces] Logged in as ...
   [Rayx Acces] Registered 17 slash commands to the main guild.
   [Rayx Acces] Synced N main-server members to the website.
   ```

4. Open a ticket in Discord via the panel to confirm the bot ↔ API link works.

---

## 4. Local development stays as-is

`server/.env` and `bot/config.json` are local-only and still win over nothing —
the code prefers env vars, falls back to the files. Nothing to change locally.

---

## Free tier instead of Starter

Render's free plan has **no persistent disks** and the service sleeps after
15 minutes idle. Consequences:

- SQLite (`/var/data`) is wiped on every deploy/restart → keys, members, admin
  account gone.
- The bot stops whenever the worker is not running (workers are not free at
  all).

If you still want a free test deploy: remove both `disk:` blocks and both
`plan: starter` lines from `render.yaml`, and delete `DATA_DIR` / `BOT_STATE_DIR`
(they will point at the ephemeral container FS). Expect empty data after each
deploy.

**Cost for the real setup (Frankfurt):** 2 × Starter instance (~$7/mo each) +
2 × 1 GB disk ($0.25/GB/mo) ≈ **$14.50/mo**.

---

## Updating

`autoDeploy: true` → every `git push origin main` rebuilds and redeploys both
services. Data on the disks survives. Pending tickets are keyed by the bot's
`state.json`, which also lives on its disk.

---

## Gotchas

- `npm ci` needs `package-lock.json` committed — it is.
- Node is pinned to `20.19.0` in `render.yaml` (`better-sqlite3` prebuilds match).
- If the bot logs `Cannot reach the Rayx Acces API`, the web service is still
  cold-starting or `BOT_API_KEY` differs between the two services.
- Changing `BOT_API_KEY` later means updating it on **both** services, then
  restarting the worker.
- Custom domain: add it to the web service, then the panel URL changes — bot
  embeds keep showing the onrender host until you set `SITE_URL` explicitly.
